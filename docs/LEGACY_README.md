# Штучна еволюція — v3.1 база → v4.0

Портовано з `artificial-evolution-v3.html` (мітка в тому файлі: **v3.0**).
Фізика формул не змінена; змінена лише інфраструктура, потрібна для
покрокової роботи за специфікацією v4.0.

## Запуск

Node окремо не встановлений, але VS Code містить Electron з Node v20.
`node.cmd` вмикає `ELECTRON_RUN_AS_NODE` і працює як звичайний node.

```bash
node.cmd scripts\verify-determinism.js 300
```

```bash
node.cmd scripts\run-headless.js --ticks=3000 --seeds=1..8 --label=my-run
```

```bash
node.cmd scripts\compare.js step0-baseline step1-internalstate
```

Візуальна версія (потрібен HTTP — через `file://` не працює, бо ядро
підключається окремими `<script>`):

```bash
python -m http.server 8099
```

далі `http://localhost:8099/index.html`.

## Що зроблено в базі (інфраструктура, не фізика)

1. **W/H/POP_CAP більше не глобальні.** У вихідному файлі це були mutable
   module-level `let`, спільні для всіх екземплярів. Розділ 12 вимагає
   порівнянь на 8+ seed'ах — а кілька `Simulation` в одному процесі
   затирали б одне одному світові константи. Тепер це поля екземпляра.
2. **Seeded RNG.** Усі ~30 точок `Math.random()` у фізиці переведені на
   явний `sim.rng`. Детермінований replay перевіряється тестом A.
3. **Checkpoint / replay.** `sim.checkpoint()` → JSON → `Simulation.fromCheckpoint()`.
   Тест C: checkpoint на півдорозі + продовження == безперервний прогін, побітово.
4. **JSONL-журнал подій.** `birth`, `death`, `bondForm`, `bondBreak`.
   `sim.drainEventLog()`; `run-headless.js --events=data/run.jsonl`.
5. **Лічильник розподілу дій** (`sim.outcomeCounts`) — write-only, фізика
   його не читає. Потрібен для порівняння «розподілу дій» між кроками.
6. **Прапорці кроків v4** (`FEATURE_DEFAULTS`). Усі вимкнені = точна
   v3.1-база. Перевірено регресією: з вимкненими прапорцями всі 8 seed'ів
   збігаються з базою до цифри.

## Крок 1 — деталі й ухвалене рішення

**Підтверджено емпірично** (`verify-internalstate-dead.js`, 4 seed'и):
прибирання доданка `(a.internalState+b.internalState)*0.1` дає побітово
ідентичний світ. Причина — `softmax(x + c) === softmax(x)`, а `c` тут
однакова для всіх 9 компонент. Тобто `infoState` і `stateChange` —
33.85% усіх взаємодій — не робили нічого.

**Ухвалене рішення щодо readout'у.** §5 каже, що `internalState` має
модулювати *поріг експресії*, але сама експресія за зарядом з'являється
аж на кроці 6. Тому на кроці 1 взято найближчий за змістом мінімальний
варіант: стан модулює **різкість** softmax'у (обернену температуру),
а не переваги.

```
beta = 3 · (1 + tanh(excitation · 0.5) · 0.5)      // 1.5 … 4.5
```

Збуджена пара чіткіше йде за найсильнішою тенденцією власних геномів;
спокійна вибирає розмито, ближче до шуму. Жодному з 9 результатів це
не дає переваги — модулюється не *що* обирається, а *наскільки строго*
геном себе виражає. Це узгоджено з майбутнім «порогом експресії» кроку 6
і не програмує результат.

**Ефект (8 seed'ів × 3000 тіків, `compare.js step0-baseline step1-internalstate`):**

- Популяційні метрики — у межах міжseed'ового шуму (4↑/4↓, знакового сигналу немає).
- Розподіл дій зсунувся системно (агрегат по мільйонах взаємодій):
  `infoState` −11.1%, `stableBond` +25.2%, `tempBond` +19.0%, `construct` −8.9%.

Цікавий наслідок, який не програмувався: `infoState` став
**самообмежувальним**. Він підіймає `|internalState|` → вибір
загострюється → перемагає власний пік геному, а не розмита середина,
якою `infoState` здебільшого й вигравав. Тобто крок 1 не просто «оживив»
дві реакції — він створив негативний зворотний зв'язок між ними.

## Відкриті питання (розділ 13) — ще не вирішені

- Чи зберігається заряд при `construct` (стехіометрія vs довільний заряд).
- Значення `k` для внеску сусідів — сканувати, не вгадувати.
- Чи гасяться заряди всередині однієї частинки, чи лише між частинками.
- Що робить домінування: приглушує ген повністю чи частково.
